`@arkosjs/react-websockets` is the reference framework binding for `@arkosjs/websockets-client` — the one that's actually been used and tested. If you're building a binding for another framework, this is the API shape to match as closely as your framework's idioms allow.

## Setup

```tsx
import { useMemo, useState } from "react";
import { Manager } from "socket.io-client";
import { WebSocketProvider } from "@arkosjs/react-websockets";

function App() {
  const [token] = useState("your-auth-token");

  const manager = useMemo(
    () =>
      new Manager("http://localhost:3000", {
        auth: { token },
        reconnection: true,
      }),
    [token]
  );

  return (
    <WebSocketProvider manager={manager}>
      <Chat />
    </WebSocketProvider>
  );
}
```

One provider at the root — every `useGateway()` call below it shares the same underlying `WebsocketClient`. The client is destroyed when the provider unmounts.

<Callout type="info">
Passing a **new `manager` instance** rebuilds the client and destroys the old one. Memoize the manager on your auth token, as above, and re-authentication works without any extra wiring — the sockets reconnect with the new token. Only the manager's *identity* is compared, so an inline `options` object won't cause repeated rebuilds.
</Callout>

## `useGateway`

One hook per namespace:

```tsx
import { useGateway } from "@arkosjs/react-websockets";

function Chat({ roomId }: { roomId: string }) {
  const chat = useGateway("/chat");
  const [messages, setMessages] = useState([]);

  chat.on(
    "receive_message",
    (data) => setMessages((m) => [...m, data]),
    [roomId] // optional: re-subscribe when this changes
  );

  return <div>{chat.status}</div>;
}
```

- `chat.on(event, handler, deps?)` — subscribes and cleans up automatically on unmount. The handler is read through a ref, so passing an inline arrow function every render does **not** tear down and re-register the listener; use `deps` when you actually want to re-subscribe (switching rooms, for example).
- `chat.status` — reactive: `"connected" | "connecting" | "reconnecting" | "disconnected"`.
- `chat.raw` — escape hatch to the underlying `GatewayClient` (and `chat.raw.rawSocket` for the raw `socket.io` socket).

## `useEmit`

For events you emit from user actions, with loading/error state handled for you:

```tsx
function MessageInput({ room }: { room: string }) {
  const chat = useGateway("/chat");
  const sendMessage = chat.useEmit("send_message");

  return (
    <button
      disabled={sendMessage.loading}
      onClick={() =>
        sendMessage.emit({ room, content: "hello" }, { ack: true })
      }
    >
      Send
    </button>
  );
}
```

- `sendMessage.emit(data, options?)` — `{ ack: true }` waits for server acknowledgement and returns a `Promise<{ success, data?, error? }>`; omit it for fire-and-forget.
- `sendMessage.loading` — reactive, `true` while an acked emit is in flight.
- `sendMessage.error` — reactive, set if the emit fails or the server returns `{ success: false }`.
- `sendMessage.lastEmittedAt` — reactive timestamp of the last emit call.
- `sendMessage.reset()` — clears `error`/`loading` manually.

## Cleanup

Handled for you — `WebSocketProvider` destroys the underlying client when it unmounts, and every `chat.on()` subscription cleans up when its component unmounts.

Because React's StrictMode mounts effects twice in development, the provider defers that teardown by a tick: a mount/cleanup/mount probe reuses the same client instead of destroying the one the still-mounted tree is rendering with.
